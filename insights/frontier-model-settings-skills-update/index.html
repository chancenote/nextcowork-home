GPT·Claude 새 모델이 나왔나요? 전역 설정과 스킬, 이렇게 점검하세요

한글날, AI 설정을 다시 정리하며 확인한 OpenAI·Anthropic 공식 가이드. 전역 지침과 프로젝트 지침을 나누고, 플러그인·스킬을 점검하는 방법과 복사해서 쓸 양식을 소개합니다.

GPT·Claude의 새 모델을 쓸 때는 전역 지침, 프로젝트 지침, 스킬을 함께 점검해 보세요.

안녕하세요. 넥스트코웍 찬스입니다.

한글날 휴일을 맞아 미뤄두었던 GPT와 Claude의 전역 설정, 맞춤 설정을 다시 정리했습니다. 새 모델이 나올 때마다 반가운 마음으로 써보지만, 정작 AI에게 건네는 업무 지침은 예전에 작성한 그대로일 수 있잖아요.

혹시 여러분도 이런 경험이 있으신가요? 보고서를 부탁했는데 원하지 않는 형식이 계속 나오거나, 간단한 수정을 맡겼는데 질문과 확인이 끝없이 이어지는 경험 말입니다. 저는 이럴 때 모델 이름과 함께 AI가 지금 어떤 지침을 읽고 있는지도 살펴보시길 권합니다.

사업을 운영하는 대표님, 제안서와 보고서를 만드는 팀장님, 직원들의 AI 활용을 돕는 교육 담당자님을 떠올리며 이 글을 썼습니다. 읽고 나시면 내 설정을 어디에 나눠 담을지 판단하고, 아래 양식을 복사해 직접 정리해 보실 수 있습니다.

동네 식당에 실력 좋은 셰프가 새로 왔다고 생각해 볼까요? 셰프에게는 우리 손님이 누구인지, 오늘 어떤 메뉴를 내야 하는지, 어떤 재료를 쓸 수 있는지 알려줘야겠죠. 모든 요리에 똑같은 조리법을 적용하라고 하면 곤란하고요.

AI와 일할 때도 저는 이 비유가 도움이 된다고 생각합니다. 다만 설정을 바꾸면 성능이 몇 배 좋아진다거나, 긴 지침을 지우면 무조건 좋아진다고 말씀드리려는 건 아닙니다. 공식 문서에서 확인한 내용과 제가 업무에 적용하기 쉽게 만든 양식을 구분해서 설명드릴게요. 공식 문서 확인 기준일은 2026년 10월 9일입니다.

1. 새 모델이 나오면 무엇부터 확인하면 좋을까요?

그 모델의 공식 사용 가이드와 이전 모델에서 옮겨갈 때의 변경 안내부터 확인하시면 됩니다. 프론티어 모델은 여기서 각 회사가 선도적인 성능을 제공하는 상위 모델을 가리키는 말로 사용하겠습니다.

OpenAI의 GPT-6 가이드에는 눈여겨볼 설명이 있습니다. GPT-6 Astra는 스킬이나 AGENTS.md 같은 지침 파일의 영향을 더 민감하게 받을 수 있으므로, 모델이 읽는 파일의 지침을 점검하라고 권합니다. 모호하거나 충돌하는 지침 때문에 작업이 일찍 멈출 수 있다는 설명도 있어요. OpenAI GPT-6 공식 가이드

Anthropic도 모델별 안내와 공통 프롬프트 원칙을 나눠 제공합니다. 특정 모델에서 관찰한 방법은 다른 모델에 적용할 때 다시 평가하라고 명시합니다. Anthropic 프롬프트 공식 가이드

그래서 저는 새 모델이 나올 때마다 다음 세 가지를 먼저 찾아보시길 권합니다.

  • 이전 모델과 비교해 지시를 따르는 방식이나 답변 형식에서 달라진 점이 있나요?
  • 내가 쓰는 도구·스킬과 관련해 수정하라는 안내가 있나요?
  • 기존 설정을 유지해도 되는지, 바꾼 뒤 무엇을 비교해야 하는지 설명하나요?

“최신 모델이니까 예전 규칙은 모두 삭제”라고 결정하기에는 범위가 너무 큽니다. 회사의 사실 정보, 고객에게 약속할 수 있는 범위, 필요한 승인 절차처럼 계속 유효한 기준도 있으니까요.

2. 전역 지침과 프로젝트 지침은 어디에 나눠 담나요?

여러 업무에 공통으로 필요한 기준은 전역에, 특정 업무의 자료와 규칙은 프로젝트에 담아보세요.

여기서 용어 하나는 짚고 갈게요. 우리가 설정 화면에 적는 ‘맞춤 지침’을 서비스 전체를 지배하는 시스템 프롬프트와 같은 것으로 이해하시면 혼동하기 쉽습니다. ChatGPT의 맞춤 지침, API의 시스템 메시지, Codex의 지침 파일은 서로 다른 설정 방식입니다. OpenAI도 사용자 화면의 맞춤 지침과 API 메시지를 구분해 안내합니다. ChatGPT 맞춤 지침 안내

일반 대화 앱과 파일을 다루는 업무 도구를 나눠 보면 한결 편합니다.

사용하는 도구여러 업무에 적용할 기준해당 프로젝트에만 적용할 기준
ChatGPT설정의 맞춤 지침프로젝트 설정의 지침
Claude설정의 Instructions for Claude프로젝트 지침
Codex기본 위치의 ~/.codex/AGENTS.md프로젝트의 AGENTS.md
Claude Code~/.claude/CLAUDE.md프로젝트의 CLAUDE.md

ChatGPT는 프로젝트 지침이 그 프로젝트 안에서 전역 맞춤 지침보다 우선한다고 안내합니다. Claude도 계정 전체 지침과 프로젝트 안에서만 쓰는 지침을 구분합니다. ChatGPT 프로젝트 안내, Claude 개인화 안내

Codex는 전역과 프로젝트의 AGENTS.md를 단계적으로 읽습니다. Claude Code는 여러 위치의 CLAUDE.md를 함께 문맥에 넣는 방식이므로, ChatGPT의 우선순위 설명을 그대로 적용하면 안 됩니다. 위 파일 경로는 기본적인 배치 예이며, 실제로 읽는 범위는 해당 도구의 설정도 확인하셔야 합니다. Codex 지침 파일 안내, Claude Code 메모리·지침 안내

개발 도구를 쓰지 않으신다면 파일 이름까지 외우실 필요는 없습니다. “쉽고 친절한 한국어로 설명해 주세요”는 공통 기준이고, “이번 고객 제안서는 이 가격표와 이 양식을 사용해 주세요”는 프로젝트 기준이라고 이해하시면 돼요.

3. ‘하지 마세요’라는 문장은 어떻게 바꾸면 좋을까요?

원하는 결과가 보이도록 구체적인 행동과 답변 형태를 적어보세요.

Anthropic은 답변 형식을 제어할 때 하지 말아야 할 것만 적기보다, 해야 할 일을 말하는 방식을 권합니다. 지시의 이유나 맥락을 함께 설명하는 방법도 안내하고요. Anthropic 답변 형식 가이드

제가 실무 문장으로 바꿔본다면 이렇게 쓰겠습니다.

기존에 쓰기 쉬운 표현제가 권하는 표현
장황하게 쓰지 마세요.결론을 먼저 쓰고, 판단에 필요한 근거와 다음 행동을 설명해 주세요.
어려운 말을 쓰지 마세요.비개발자인 대표가 이해할 수 있게 설명하고, 전문용어는 처음 나올 때 풀어주세요.
대충 보고서를 만들지 마세요.보고서에 고객 문제, 선택지, 추천 이유, 확인할 조건을 담아주세요.
무조건 짧게 답하세요.일반 질문은 간결하게 답하되, 문서 작성은 요청한 분량과 완성도를 지켜주세요.

“CEO 보고용으로 써주세요”도 출발점은 되지만, 내가 어떤 결정을 해야 하는지까지 알려주시면 더 구체적인 요청이 됩니다.

다만 금지문을 모두 없애라는 뜻은 아닙니다. 기밀정보 공개 금지나 승인 없는 외부 발송 금지처럼 지켜야 할 경계는 명확하게 남겨두세요. 말투를 다듬는 일과 권한을 바꾸는 일은 구분해서 다루시면 좋겠습니다.

4. 지침은 무조건 짧을수록 좋을까요?

필요한 정보는 남기고, 중복과 모호함을 줄이는 쪽으로 정리하시면 됩니다.

OpenAI의 추론 모델 가이드는 목표와 제약을 간단하고 직접적으로 전달하고, Markdown 제목이나 XML 태그로 입력의 구획을 나누라고 권합니다. 내부 추론을 하는 모델에 “단계별로 생각하라”는 지시를 반복할 필요도 없다고 설명합니다. 이 안내는 추론 모델에 관한 것이므로 모든 모델·모든 작업의 절대 규칙으로 넓혀 읽지는 않겠습니다. OpenAI 추론 모델 활용 가이드

Claude Code 가이드는 CLAUDE.md에 폭넓게 적용되는 내용을 남기고, 가끔 필요한 전문 지식과 작업 절차는 스킬로 옮기라고 안내합니다. 불필요하게 비대한 지침 파일을 경계하라는 취지입니다. Claude Code 실무 가이드

저는 지침의 각 문장 옆에 네 가지 중 하나를 적어보시길 권합니다.

판단이런 내용에 적용해 보세요
유지여러 업무에서 계속 필요한 말투, 사실 확인 원칙, 권한 경계
이동특정 고객·프로젝트에서만 쓰는 자료와 문서 형식
수정‘항상’, ‘무조건’이 실제 적용 범위보다 넓게 쓰인 규칙
보관 후 제외더 이상 사용하지 않는 도구나 종료된 업무의 지침

길이를 줄이려고 중요한 기준 자료까지 빼지는 마세요. 저는 “몇 글자 이하인가”보다 이 지침이 언제, 왜 필요한지 설명할 수 있는가를 먼저 보시길 권합니다.

5. 바로 복사해서 쓸 지침은 어떻게 작성하나요?

공통 협업 방식과 프로젝트의 업무 조건을 두 문서로 나눠 작성해 보세요. 아래는 공식 문구를 그대로 옮긴 것이 아니라, 앞의 원칙을 바탕으로 제가 만든 업무용 예시입니다. 여러분의 역할과 승인 범위에 맞게 고쳐 쓰시면 됩니다.

여러 업무에 공통으로 사용할 지침

## 나와 일하는 방식
- 나는 AI를 업무에 활용하는 비개발자입니다. 쉬운 한국어 경어체로 설명해 주세요.
- 결론과 업무상 의미를 먼저 말하고, 판단에 필요한 근거를 이어서 설명해 주세요.
- 확인된 사실, 가정, 제안을 구분하고 중요한 사실에는 확인 가능한 출처를 붙여주세요.
- 설명 요청에는 설명을, 실행 요청에는 승인된 범위의 결과물과 필요한 확인을 제공해 주세요.
- 결과를 크게 바꾸는 필수 정보가 없으면 질문하고, 사소한 선택은 가정을 밝히고 진행해 주세요.
- 일반 답변은 간결하게, 문서와 콘텐츠는 요청한 독자·분량·문체에 맞게 완성해 주세요.
- 말투와 형식의 기본값은 이번 요청에서 명시한 요구에 맞춰 조정해 주세요.
- 외부 발송·공개·삭제·비용 발생은 내가 승인한 대상과 범위 안에서 진행해 주세요.

이 마지막 두 줄은 서로 다른 역할을 합니다. 형식은 요청에 맞춰 유연하게 바꾸고, 실행 권한은 승인 범위를 지키도록 적은 것입니다. 지침 한 줄로 서비스나 조직이 정한 접근 권한이 바뀌는 것은 아닙니다.

고객 제안서 프로젝트에 사용할 지침

## 프로젝트 목적
[고객 유형]이 [해결할 업무 문제]를 판단할 수 있는 제안서를 만듭니다.

## 기준 자료
승인된 서비스 소개: [문서 이름 또는 경로]
현재 적용할 가격과 범위: [문서 이름·기준일]
고객 요구사항: [미팅 기록 또는 요청서]

## 작성 기준
고객 문제, 제안 범위, 제공 결과물, 일정 조건, 비용 조건, 다음 행동을 담아주세요.
자료에 없는 실적과 확정되지 않은 조건은 사실처럼 쓰지 말고, 확인할 항목으로 구분해 주세요.
자료가 충돌하면 해당 문서와 차이를 제시해 주세요.

## 완료 기준
주요 주장과 수치의 출처를 확인하고, 아직 결정이 필요한 항목을 정리해 주세요.
이번 요청의 승인 범위는 [초안 작성 / 내부 검토 / 고객 발송 중 해당 범위]입니다.

전역에 고객마다 다른 가격표까지 넣어두기보다, 해당 프로젝트에서 최신 자료를 지정하는 방식입니다. 대괄호 부분은 실제 값으로 채운 뒤 사용해 주세요.

6. 플러그인과 스킬이 많아졌다면 무엇을 손봐야 하나요?

어떤 작업에 호출되는지, 무엇을 수행하는지, 어떤 자료를 읽는지부터 확인해 보세요.

용어부터 쉽게 풀어볼게요. 스킬은 반복 업무의 절차와 자료를 묶은 작업 안내서에 가깝습니다. 플러그인은 스킬이나 외부 도구 연결 등을 설치하고 공유할 수 있게 묶은 패키지로 이해하시면 됩니다. 세부 구성은 제품에 따라 다릅니다. OpenAI 스킬·플러그인 안내, Claude Code 플러그인 안내

OpenAI의 스킬 문서는 먼저 이름과 설명을 읽고, 사용할 스킬이 정해지면 상세 지침을 불러오는 방식을 설명합니다. Claude Code도 일반 세션에서 스킬의 설명과 전체 본문을 구분해 불러옵니다. 긴 참고 자료는 별도 파일로 나눠 필요할 때 읽도록 구성할 수 있어요. OpenAI 스킬 작성 안내, Claude Code 스킬 안내

그러니 설치 개수만 세기보다 AI가 어느 상황에 어떤 스킬을 골라야 하는지를 먼저 살펴보세요. 제가 권하는 점검표는 다음과 같습니다.

예를 들어 ‘제안서 작성 스킬’의 설명은 이렇게 다듬어볼 수 있겠습니다.

필요한 입력: 고객 문제, 승인된 서비스 자료, 비용·일정 조건입니다.

또 한 가지 참고할 내용이 있습니다. Anthropic은 Claude Opus 4.5·4.6에서 도구 사용을 강하게 강제하던 문구가 오히려 과도한 호출로 이어질 수 있어, 표현을 완화하라고 안내한 바 있습니다. 그 모델들에 관한 구체적인 안내이지, 모든 모델에서 ‘반드시’라는 말을 지워야 한다는 뜻은 아닙니다. Anthropic 도구 사용 가이드

새 모델의 안내를 읽고, 내 스킬에 해당하는 규칙만 골라 조정하시면 됩니다.

7. 설정을 바꾼 뒤에는 무엇을 비교해야 하나요?

자주 맡기는 실제 업무를 같은 기준으로 비교해 보세요.

OpenAI는 느낌만으로 결과를 평가하기보다 실제 업무에 맞는 평가 기준을 정하고, 일반적인 상황과 예외 상황을 포함해 반복 확인하라고 안내합니다. OpenAI 평가 가이드

이를 개인 업무에 적용한다면, 저는 아래 순서로 시작하시길 권합니다. 정해진 공식 시험 절차가 아니라 여러분이 부담 없이 해볼 수 있도록 정리한 방법입니다.

  1. 현재 지침과 플러그인·스킬 버전을 기록해 되돌아갈 기준을 남겨주세요.
  2. 사용할 모델의 공식 가이드에서 내 업무와 관련된 변경점을 찾으세요.
  3. 중복 규칙이나 호출 조건처럼 한 종류의 문제부터 수정해 주세요.
  4. 같은 모델과 같은 자료로 기존 지침과 수정 지침의 결과를 비교해 보세요.
  5. 개선된 부분과 나빠진 부분을 확인한 뒤 적용 여부를 결정해 주세요.

모델과 지침을 한꺼번에 바꾸면 무엇 때문에 결과가 달라졌는지 구분하기 어렵습니다. 가능하다면 ‘새 모델 + 기존 지침’과 ‘새 모델 + 수정 지침’을 비교해 보세요. 대화 기록과 메모리 등 결과에 영향을 줄 수 있는 조건도 함께 적어두시면 좋겠습니다.

자주 묻는 질문

새 모델이 나오면 기존 지침을 모두 지워야 하나요?

모두 지우기보다 원본을 보관한 뒤, 공식 안내와 실제 결과를 기준으로 필요한 부분부터 바꿔보세요. 지금도 유효한 업무 기준과 권한 경계는 유지할 이유가 있습니다.

지침 충돌을 없애면 AI의 환각도 없어지나요?

지침을 정리했다고 사실 오류가 사라진다고 보장할 수는 없습니다. 중요한 주장과 수치는 원본 자료에 대조하고, 확인되지 않은 내용은 구분해서 사용해 주세요.

ChatGPT와 Claude의 설정을 똑같이 복사해도 되나요?

공통으로 원하는 말투와 업무 원칙은 재사용할 수 있지만, 지침을 읽는 위치와 적용 범위는 제품별로 확인해야 합니다. 특히 Codex·Claude Code의 파일 설정을 일반 대화 앱의 설정과 동일하게 취급하지 마세요.

오늘은 어떤 설정부터 열어보면 좋을까요?

가장 자주 쓰는 AI의 전역 지침을 열고, 특정 업무에만 필요한 문장 하나부터 찾아보세요. 그 문장을 알맞은 프로젝트나 스킬로 옮겨보는 것으로 시작하셔도 좋겠습니다.

저는 AI와 잘 일하려면 ‘좋은 답변’이 내 업무에서 무엇인지 설명할 수 있어야 한다고 생각합니다. 누구에게 보여줄 결과인지, 어떤 자료를 따라야 하는지, 어디까지 맡기는지 말입니다. 새 모델을 만나는 날은 이 기준을 다시 정리하기 좋은 기회겠죠.
